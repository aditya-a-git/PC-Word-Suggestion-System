# PCWord dictionary builder

This build-time Python tool reads the SQLite database generated by the pinned ESDB source checkout and writes a deterministic, metadata-preserving UTF-8 TSV. PCWord itself remains a .NET-only offline application.

```powershell
git clone --depth 1 --branch rel-2026.02.25 https://github.com/en-wl/wordlist.git .\_esdb-source
Push-Location .\_esdb-source
$env:PYTHONUTF8 = '1'
python .\combine.py create-db .\scowl.db
Pop-Location
python .\tools\PCWord.DictionaryBuilder\build_dictionary.py --database .\_esdb-source\scowl.db
```

The source tag resolves to commit `7e99edab8e32f9f9ea2b15f249ca8d4d67237410`. The builder uses SCOWL size 60, spelling codes A (American), B (British `-ise`), and Z (British `-ize`), and variant levels 0 through 6. The JSON configuration records these defaults. Commonness is represented by the source's minimum SCOWL size, not by corpus frequency.

The builder excludes proper-noun POS rows, upper-only forms, nonword/special/word-part classes, offensive/vulgar level 1 and 2 usage notes, and tokens the existing controlled editor cannot capture as one word. It preserves accepted inflections, dialect memberships, source variant group IDs, part-of-speech codes, lemma words, variant level, and commonness size. Every exclusion rule is explicit in `config.json` and the build report lists filtered rows and unique forms. Dialect totals overlap because shared spellings belong to each dialect.

The generated format has a version header and seven tab-separated fields: word, dialect codes, ESDB variant-group IDs, minimum SCOWL size, POS codes, variant level, and lemma words. Rows are NFC normalized and sorted deterministically. The runtime loader validates this format; the compiled app requires neither Python, SQLite, nor a network connection.

The upstream `Copyright` notice is retained in `THIRD-PARTY-NOTICES.md`. Regeneration uses only the selected size-60 official spelling vocabulary, not the optional Australian or UKACD lists.
